# 流程批量分配接口接入（2026-10-19）

来源：`http://192.168.0.140:48080/v3/api-docs/flycowerp` 中 `Flow_batchAssign`。接口为 `POST /admin-api/flycowerp/flow/assign/batch`，只支持同一节点统一分配，响应为 `CommonResult<Boolean>`。

## 页面入口

制图流程下的 AI 图片生成任务分配、修图任务分配、页面制作任务分配、上新任务分配列表支持当前页勾选及“批量分配”。仅有对应节点权限的员工可用，员工范围继续固定为本人当前节点任务，管理人员可查看当前节点全部处理人的任务。

冻结、完成、终止、草稿、节点上下文缺失的任务不可勾选。查询、刷新、换页和切换节点清空勾选，避免跨页误选。弹窗展示所选款号和处理人，只提供一个统一处理人选择器，使用既有用户查询接口。

## 请求契约

应用请求客户端已统一配置 `/admin-api`，API 封装只拼接 `/flycowerp/flow/assign/batch`，避免重复前缀。

```json
{
  "nodeKey": "retouchTaskDispatch",
  "tasks": [
    { "procInstId": "example-process-1", "nodeTaskId": "example-task-1" },
    { "procInstId": "example-process-2", "nodeTaskId": "example-task-2" }
  ],
  "unifiedAssigneeId": "example-user-id",
  "unifiedAssigneeName": "示例处理人"
}
```

- `tasks` 必须非空，节点必须一致；流程与节点任务标识保持字符串，不转换为数值。
- 不发送 `assignMode`、`styleAssignList`、普通上新任务 ID 等额外字段。
- 批量接口目前未提供 `remarkInfoVO`，弹窗不采集无法保存的备注附件；单任务分配继续支持必填备注和最多 6 张附件。
- 提交前重新查询固定节点及员工范围，复核每个任务仍存在、可处理，且流程实例与节点任务标识和勾选时一致；异常或已流转/转派/冻结时停止发送批量请求。服务端仍需负责最终权限和状态校验。
- 请求期间阻止重复提交、关闭弹窗和应用内切换任务页面。只有 `data === true` 才提示成功，并刷新列表及数量、清空勾选。Boolean false、业务异常或请求失败均保留选择和表单，不自动重发；手动重试前重新复核任务。

## 仍需后端明确

Boolean 无法表达单项结果，本次不推断全成功/部分成功的事务语义。后续如需逐项失败展示和精确重试，应提供每项结果及事务约定；如需满足原型的批量分配备注附件，应增加可持久化字段。

## 验证

- TypeScript 类型检查、修改文件 ESLint 及生产构建通过。
- 本地 Chrome 模拟请求通过：四类分配节点入口、必选处理人、冻结/缺节点信息禁选、同节点精确请求体、字符串大 ID、成功刷新总数。
- 查询/刷新/换页清空勾选；处理人列表失败重试；Boolean false 及业务异常保留表单；不自动重发，手动重试先重新复核。
- 提交前冻结、节点任务标识变化、跨节点流转、任务消失均在批量请求前拦截；连续点击与请求中重复点击只发一个批量请求；应用内页面切换在请求期间被拦截。
- 员工提交前查询仍固定本人，转派后不再可处理；后端忽略范围筛选时停止提交；无权限路由被拦截，非分配节点不显示批量控件。无页面运行异常。
