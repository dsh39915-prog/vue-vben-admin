# 搭配方案按表格款式初始化（2026-10-21）

按用户最新要求，AI 搭配方案输出不再手动“添加搭配方案”，商品服饰图固定一张不可编辑的主服饰，其余图片均为搭配服饰。

## 数据来源与初始化

- 用户确认使用 `GET /admin-api/flycowerp/newProductStyle/list?taskId=...`，读取 `styleNo/styleName/clothingProductUrl`。每条款式数据自动生成一个方案，款号和颜色锁定；不提供手动增加或删除方案入口。
- 同时读取现有搭配方案，以款号和颜色匹配，保留方案 ID、已填写素材和合拍标记。表格重复款号颜色、已有方案重复或方案已不属于表格时提示核对，避免错误合并或静默丢失方案。
- `clothingProductUrl` 兼容实际图片对象、序列化 JSON 和普通 URL，统一转换为三种图片地址。普通 URL 用同一地址预览；多图来源不擅自挑选，返回数据异常提示。
- 自动初始化仅用于搭配输出节点；其他节点查看已有方案，不把尚未保存的表格模板冒充已提交方案。

## 主服饰与辅服饰

- 主服饰图来自当前款式 `clothingProductUrl`，固定显示一张，无上传、替换、删除、款号修改或主服饰勾选操作。
- 2026-10-22 更新：“添加辅服饰图”改为调用 `GET /admin-api/flycowerp/newProductStyle/queryMatchStyleList?styleNo=...` 模糊查询。使用后端返回的候选款式，不再局限于当前任务列表，也不在前端再次做字面筛选。输入延迟查询、回车立即查询，空输入不请求；详情和验证见 [辅服饰远程查询](matching-style-search-2026-10-22.md)。
- 选择后带出该候选的真实款号和图片地址，辅服饰可移除，不能切换成主服饰；已选图片和当前主图不能重复添加。
- 保存/提交前重新组装服饰数组：当前表格主图在首位且 `isMain=1`，其他图全部 `isMain=0`。历史额外主图保留为搭配服饰；与当前主图相同的图片只保留固定主图。表格缺少主服饰图时显示提示，允许暂存但拦截提交，不允许手工指定其他图片顶替。
- 保留原有节点权限、冻结只读、备注、附件及保存/提交行为。选择辅服饰期间暂停保存和离开任务；请求失败保留选择。
