# 超级管理员流程菜单修复（2026-10-20）

## 原因

只读查询测试服务的 /admin-api/system/auth/get-permission-info：admin 用户的 roles 包含 common、super_admin，但 permissions 没有 *:*:*，也没有 flycowerp:drawing:* 权限码。旧前端仅通过权限码识别流程管理员，因而过滤了“上新管理”和“制图流程”。

## 修复范围

- 登录和刷新恢复会话时，识别后端内置角色码 super_admin，仅补充 flycowerp:drawing:manage，统一用于菜单、路由和任务范围。
- 恢复上新任务、人工工作台、流程管理、流程定义和全部 15 个制图节点；制图职责入口及其操作继续要求现有系统授权权限码。
- 不生成全局 *:*:*，不补充系统查询或授权权限；不根据用户名 admin、用户 ID 或通用角色名 admin/super 判断。
- 员工继续按显式节点权限码过滤，只查询本人当前环节任务。
- 不修改服务端用户、角色或授权。接口实际授权仍由后端执行。

## 使用

更新后完整刷新页面即可重新读取角色和权限并生成菜单；也可退出后重新登录。

## 验证

权限单元测试覆盖超级管理员缺少流程权限码、无全局或系统提权、已存在权限不重复、普通员工节点范围及无效节点路径。
浏览器使用模拟接口验证登录、刷新和直接 URL 的流程访问，以及系统页面仍按原权限拦截；写操作不发送到真实服务。

验证结果：11 项单元测试通过（含 8 项流程权限策略测试）；管理员登录/刷新/直接访问与员工隔离浏览器回归通过；TypeScript、ESLint、格式检查及生产打包通过。
