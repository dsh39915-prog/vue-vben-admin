# AI 图片生成结果接口更新（2026-10-21）

依据 `192.168.0.140:48080` 最新 flycowerp Swagger 和用户提供的原型截图，接入本地结果图片新增、删除及查询来源字段。

## 接口

| 接口 | 接入方式 |
| --- | --- |
| `POST /admin-api/flycowerp/aiImageResult/save` | JSON 提交 `businessKey`、必选图片批次 ID `imgId`、`originalUrl`、`previewUrl`、`thumbnailUrl`；文件先通过现有 `POST /flycowerp/temp-image/upload` 上传取得三种地址 |
| `GET /admin-api/flycowerp/aiImageResult/delete/{id}` | 使用图片结果记录 `id` 删除，按文档使用 GET；业务码 `code=0` 即删除成功并刷新列表，不再判断 `data` 是否为 `true` |
| `GET /admin-api/flycowerp/aiImageResult/list/{businessKey}/{imgId}` | 保留已有双路径参数，图片列表新增 `id`、`isAiCreate` 类型和展示；`0` 为本地上传，`1` 为 AI 生成，未返回标记时显示来源未知 |

最新保存接口已增加 `imgId`（integer/int32），按用户要求作为必选字段提交。上传弹窗使用当前任务的批次下拉数据，从单批次进入自动带入该 ID；从全部批次进入必须手动选择具体批次，未选时不会上传文件或保存结果。上传/保存期间锁定批次，失败重试保留批次及已上传地址。`creator/updater` 未标必填，前端不代填审计人员。

上传保存后重新查询批次下拉和结果：全部批次视图保持全部，单批次视图展示上传时选定的批次。删除后优先保留原批次，批次已不存在时切换至全部批次。未自行拼造结果记录或批次。后续已按最新接口补齐[全部批次查询](./ai-image-result-batches-2026-10-21.md)。

## 页面

- 生图节点工作台（模特图、动作图）的“生成结果与历史”页签增加“上传本地图片”；图片标注“本地上传 / AI 生成”，仅本地图片展示带二次确认的删除操作，与原型对应。
- AI 创作 → 图片生成结果 → 按流程任务查询，复用相同组件和操作。没有可用批次时禁用本地上传，并提示先生成图片批次。
- 冻结、已完成或其他不可编辑任务继续只读。工作台通过现有节点、处理人及任务状态策略控制编辑，不增加菜单授权范围。
- 上传和保存分两步；保存失败保留已上传地址，重试无需重复传文件。文件更换后清除旧地址；上传失败或返回地址不完整时不保存结果。
- 请求期间阻止重复提交、关闭上传框、切换批次/流程任务和离开路由；全局结果页也禁止切换到“全部结果”造成上传组件卸载。删除以业务码判定：`code=0` 时即使 `data` 为 `false`、`null` 或未提供也提示成功并刷新；非零业务码或网络失败保留原结果，允许重试。统一请求拦截器负责业务码校验。
