# 公网管理后台防爬与防刷

后台保持公网账号登录，不设置 IP 白名单。前端直接访问 `https://qq.i4.cn`，本文配置不增加 API 前缀、不改变现有 API 路由或转发目标。

## 已加入仓库

- `public/robots.txt` 对所有爬虫声明 `Disallow: /`。
- 页面入口声明 `noindex,nofollow,noarchive,nosnippet,noimageindex`；构建检查验证这些禁止收录配置存在。
- 随附静态站点配置为成功及错误响应添加 `X-Robots-Tag`，包括带独立缓存规则的资源响应。
- 请求限流配置超过阈值返回 HTTP `429`、JSON 提示及 `Retry-After`；不会把限流误报为登录失效。

搜索引擎规则用于减少抓取和收录，不是身份验证。若网站已被收录，需要在相应站长平台申请移除；被 `Disallow` 阻止的爬虫可能无法重新读取页面上的 `noindex`。恶意机器人仍应由鉴权、验证码和服务端限流约束。

## 入口限流规则

| 范围 | 当前配置 | 突发额度 | 超限提示 |
| --- | --- | --- | --- |
| 同一 IP 的登录、短信验证、重发短信 POST | 平均 30 次/分钟 | 10 次 | HTTP 429，建议 60 秒后再试 |
| 同一 IP 的其余页面和接口请求 | 平均 20 次/秒 | 60 次 | HTTP 429，建议 1 秒后再试 |
| `/js/`、`/css/`、`/jse/` 及站点图标等静态资源 | 不计入上述额度 | — | 保留正常并发加载与缓存 |

这里使用 Nginx 漏桶平均速率，突发额度不是固定时间窗口的总请求数。阈值可结合实际办公 NAT、访问量和监控调整。没有按 User-Agent 名称封禁，也没有加入前端可绕过的“防机器人验证”。

## 部署位置

仓库的 `nginx.conf` 已引入以下三个文件，Docker 镜像会一并复制：

1. 在 `http` 块引入 `anti-bot-http.conf`，定义共享计数区。
2. 在现有 `qq.i4.cn` 的 `server` 块引入 `anti-bot-server.conf`，执行限流和 429 响应。
3. 已经单独设置 `add_header` 的 `location` 应同时引入 `anti-bot-headers.conf`，避免 Nginx 的头部继承规则导致禁止收录头丢失。

将这些文件放在主配置同目录，先运行 `nginx -t`，成功后再重载。不要通过替换整个正式站点配置的方式丢弃已有 API 服务。源码仓库中的配置更新不会自动更改正在运行的正式服务器。

如果只把前端 `dist` 上传到现有静态目录，`robots.txt` 和 HTML 标记会生效；请求限流仍需把上述规则加到实际处理页面/API 请求的入口。仅配置独立静态容器时，只保护到达该容器的请求，不能保护绕过它的后端端口。若使用其他网关或 WAF，可按相同范围配置等效规则。

在 CDN 或代理之后部署时，只信任明确列出的代理地址来解析真实客户端 IP；不要直接信任客户端任意填写的 `X-Forwarded-For`。否则可能绕过限流，或把所有用户都计入一个代理 IP 的额度。现有 `location` 如果自行配置 `limit_req`，需同时保留这里的规则，避免覆盖继承的限制。

## 需要后端执行的规则

此仓库不含后端运行服务，以下规则必须在后端实现或核对，不能靠浏览器保证：

- 所有管理 API 校验 Bearer 令牌和操作权限，未登录返回 `401`，权限不足返回 `403`。
- 按账号记录失败次数，连续失败时升级验证码和临时冷却，防止更换 IP 继续尝试；保留已有服务端验证码校验。
- 短信发送同时按账号、手机号和 IP 限制，服务端执行重发间隔与每日额度；前端倒计时只作为提示。
- 数据查询按已认证用户限流、限制每页数据量；写入接口防止重复提交。导出等高开销操作另设并发与频率额度。
- 网关入口之外的后端源站端口不应对公网开放，避免绕过入口规则。

2026-11-27 只读检查：公开验证码配置返回 HTTP `200`；未携带登录令牌时，`GET /api/system/auth/me` 和 `POST /appInfo/list` 均返回 `401`。这确认了这两个受保护接口的未登录拒绝行为，不代表已逐个审计所有 API 的权限或测量了正式环境限流。

## 本地验证

随附 Nginx 配置已通过语法检查，并在本机隔离服务中验证：`robots.txt` 返回文本规则，入口与 404 响应包含禁止收录头，登录及普通接口突发请求触发 `429` 和相应 `Retry-After`；限流触发后，80 个并发哈希资源请求仍全部返回 `200`。测试的 API 上游为本机测试服务，没有向正式站点发送高频请求。
