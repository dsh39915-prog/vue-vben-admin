# 2026-11-27 第二轮优化验证

## 已处理

- 退出立即清理本地会话并导航到登录页。服务端撤销使用退出时捕获的 Bearer 令牌独立执行，不等待服务端响应；重复点击合并导航。旧撤销成功或失败均不能清理随后建立的新会话。
- 空目录和过滤后无有效子菜单的目录不生成页面路由，不作为首页落点；实际菜单的组件缺失仍保留原有 404 提示。
- 路由组件加载失败显示不依赖懒加载业务模块的恢复界面，隐藏旧页面。重新加载完整目标地址，保留查询参数与定位；也可直接返回登录。过期导航的错误不能覆盖新页面。
- 锁屏时钟和日期按应用时区格式化，上海午夜显示 `00` 点，避免使用设备时区。
- 后台组件、通用表单、加载指令、Tippy 和 Motion 在进入后台前初始化，并对并发导航去重。登录页不再等待这些模块；首次刷新后台仍保留启动提示直至路由就绪。

## 登录首屏对比

同一台机器、同一无头 Chromium、全新浏览器上下文、同一 Nginx gzip 静态服务和隔离 API 数据。统计首次打开登录页并移除启动遮罩后的 JS 资源，不包含登录后才加载的后台模块；不是公网耗时或性能评分。

| 指标       | 优化前         | 优化后       | 变化       |
| ---------- | -------------- | ------------ | ---------- |
| JS 资源数  | 41             | 40           | 减少 1 个  |
| 解压后 JS  | 2,062,088 字节 | 868,978 字节 | 减少约 58% |
| gzip 后 JS | 574,106 字节   | 305,681 字节 | 减少约 47% |

数据已按相同方式在最终发布包中复测。52 个测试文件、338 项测试通过；类型检查、规范检查和生产构建通过，ZIP 与 `dist` 内容一致性校验通过。

## 已执行的隔离浏览器场景

1. 纽约设备时区下锁屏显示上海时间，日期由应用时区决定；输入锁屏密码可正常解锁，验证按需初始化后的通用表单仍可使用。
2. 阻断客户端壳开关的页面 JS 后，出现恢复操作，旧表格不再显示；恢复资源后点击重新加载可正常进入目标页。
3. 暂停旧退出接口响应，确认本地已回到登录页；再次登录后释放旧退出的 HTTP 401，新的令牌和页面仍保留，且不显示旧会话错误提示。
4. 接口菜单首项为空目录时，登录进入下一项有效页面，导航中不出现空目录。

上述均使用隔离测试账号、模拟接口和本地生产包，不代表真实生产账号或服务端撤销策略已经验收。依赖跨主版本的剩余项继续按 [依赖升级记录](DEPENDENCY-REVIEW.md) 跟进。

## 2026-11-28 更新检测修复

- 每次构建生成不含账号或环境信息的构建标识，同步内置到页面代码和 `app-version.json`。首次检查直接与当前页面比较，避免发布发生在首次轮询前时漏报。
- 进入后台和切回可见标签页立即检查；检查完成后按原配置间隔安排下一次，默认一分钟。同一时刻只有一个有效请求，超时十秒取消；隐藏或卸载时清理请求与定时器，旧响应不能重启轮询或覆盖新请求。
- 只采纳成功 HTTP 响应中的有效版本文件，不再使用 ETag 或 Last-Modified 判断更新。错误响应、重定向、无效 JSON 和网络失败不提示刷新，后续周期重试。
- 新增 23 项回归测试通过，覆盖构建标识一致性、首轮即遇新版、超时、取消和旧响应等场景；前端类型检查及修改文件 ESLint 通过。
- 全仓单元回归通过：87 个测试文件、635 项测试成功。原有表单必填校验及会话失效场景的预期日志不计作测试失败。
- `pnpm build:release` 通过，新增版本文件已包含在 ZIP 中；发布校验确认其标识在页面代码中存在，且 ZIP 与 `dist` 文件内容一致。
- 本地生产包的隔离浏览器验证通过：同版不提示，503 不误报，首次检查到新版出现“新版本可用”弹窗；无意外浏览器错误。测试不连接真实认证或业务服务。

部署及回滚时，`app-version.json` 需要与入口使用同一个构建包，详见 [上线说明](RELEASE.md)。
